## Where the project stands

Every feature on the MVP list is implemented. The whole loop — Korean or English request → real
Gemma on the Fold8 → tool selection → strict decoding → validation → confirmation → durable claim
→ device write → trusted receipt → final answer — has run on the physical device.

| Layer | What exists |
|---|---|
| `core:llm` | Pinned LiteRT-LM 0.16.1, SHA-256 verified model import, GPU/CPU runtime |
| `core:agent` | Turn controller, closed tool registry, strict flat-JSON argument reader |
| `core:tools` | Tool contracts, confirmation policy, execution interlock, durable SQLite ledger, calendar/alarm/notification/route/search tools, one HTTP transport |
| `core:data` | Room conversations + messages + captured notifications, DataStore settings, Keystore AES-GCM vault |
| `core:diagnostics` | Bounded content-free JSONL, exit checkpoints |
| `app` | Compose UI, setup cards, chat history, notification listener, interlock implementation |

Tools registered: `calendar_query`, `calendar_create_event`, `calendar_update_event`, `alarm_set`,
`alarm_next`, `kakao_notification_search`, `route_estimate`, `web_search`.

Counts as of this writing: 209 host unit tests, 84 Fold8 instrumentation passes with 13 intentional
skips, clean lint, both APKs building, release APK signed and verified.

## What is proven on hardware, and what is not

Proven on the Fold8:

- real Gemma selecting a tool and producing valid arguments, in **both** English and Korean;
- the trusted date preamble resolving "tomorrow" / "내일" correctly;
- the confirmation gate in **both** directions — approving wrote the event, denying recorded
  `tool_not_executed` and wrote nothing;
- `adb install -r` preserving the app-private 3.66 GB model (with the debug key);
- one tool-calling turn at 57.7s against the 120s deadline, thermal staying `none`/`light`.

**Not** proven, and marked as such in the status ledger:

- **No live NAVER network request has ever been made.** `route_estimate` and `web_search` are
  tested against recorded response shapes only. Treat "the recorded shape matches production" as
  an assumption until someone runs it with real keys.
- **No conversation summary has been generated by the model.** The threshold logic, prompt
  construction, and storage are tested; quality and added latency are unmeasured.
- **KakaoTalk capture is not verified end to end.** A test cannot post a notification as another
  package, so only the rejection path was observed on hardware.
- Korean tool selection is one phrasing, one run. Not an accuracy measurement.

## Open decisions — these are the owner's, not an agent's

1. **Back up the signing key.** `app/personal-edge-release.jks` and its password exist and produce
   a verified signed APK (certificate SHA-256 `e0f66d4b4c8064db6a9d46097d77903cf13fbccacbdfc6e49e9f7c380b8e457a`).
   Both files are gitignored and must stay that way. Without an offline copy, losing the machine
   means no update can ever preserve app data again.
2. **When to migrate the phone from debug to release.** It costs an uninstall and a 3.66 GB model
   re-import. See [`RELEASE_AND_BACKUP.md`](RELEASE_AND_BACKUP.md).
3. **What to do about NAVER Calendar.** Measured on the device: a `com.nhn.android.naveraccount`
   account exists and publishes **zero** rows into `CalendarContract`. The naver.com-named
   calendars are Samsung account calendars. The Open API is create-only and official CalDAV help
   says Android is unsupported. So there is no read/write transport today. The options are to use
   a different calendar, to add create-only NAVER Open API support behind OAuth, or to drop it.
   Do not treat an account name as evidence of a transport.
4. **Credentials for the network tools.** Four slots exist in settings; nothing is stored yet, so
   `route_estimate` and `web_search` refuse during validation.

## Traps that already cost something

- `connectedAndroidTest` uninstalling the app destroyed the imported model once. Guarded now via
  `gradle.properties`; see AGENTS.md.
- Shell heredocs silently wrote raw NUL bytes into two source files. A repo-wide scan is cheap:
  they are invisible in every editor and diff.
- `verify-release-signing.sh` had two bugs that only appear when a key exists — it demanded v2
  when AGP emits v3, and its grep never printed the fingerprint it told you to record. Exercise
  scripts with a disposable fixture rather than trusting them unrun.
- An earlier claim that NAVER Calendar reaches the device over CalDAV was wrong and had to be
  retracted. Verify provider facts against the device or official docs before writing them down.
- A `치과 일정` event dated 2026-08-23 15:00 sits in the device's local calendar. No turn in this
  app's diagnostics created it, so its origin is unestablished and it was left alone.
