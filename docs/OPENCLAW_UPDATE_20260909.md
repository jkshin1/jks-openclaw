# OpenClaw 2026.9.3 및 새 작업 흐름

2026-09-09 KST. 현재 Mac/Telegram 배포에 관한 기록입니다.

## 적용한 런타임

- OpenClaw 2026.9.3, 공식 Codex 플러그인 2026.9.3, 기존 Node 26.5.0.
- 기본 대화 모델은 GPT-6 Astra/high, 요약은 기존 Sol/low ChatGPT OAuth입니다.
- 소유자 Telegram 대화 식별자, 소유자 allowlist, 네이티브 Codex 이력 격리, 유료 모델 자동 대체 금지를 보존했습니다.
- 공식 업데이트에 포함된 후보 검증·복구, 세션 응답성·캐시, Telegram 사진 묶음·내부 표시 정리 개선을 함께 적용했습니다.
  개별 기능의 전체 성능이나 Telegram 사진 앨범 수신을 모두 실측했다는 뜻은 아닙니다.

공식 변경 사항은 [2026.9.3 릴리스](https://github.com/openclaw/openclaw/releases/tag/v2026.9.3),
업데이트 절차는 [공식 CLI 문서](https://docs.openclaw.ai/cli/update)에 있습니다.

## 네 로컬 패치의 호환성

| 패치 | 새 버전에서의 검증 |
| --- | --- |
| Telegram 전송 복구 | 소유자·계정·기간 제한, SQLite 소유권 경쟁, 실패 보존, 별도 프로세스의 복구와 중복 재실행 방지 |
| GLM 토큰 필드 | 이동한 AI 호환성 모듈에서 실제 요청 기본값이 `max_tokens`가 되는지 확인; 다른 모델·명시적 override 보존 |
| GLM max 추론 | 실제 메뉴·스트림·요청 생성 경로 33개 검증; 수동 GLM 선택만 대상 |
| 메모리 세션 제외 | 모든 대화 유형 제외 시 메타데이터 없는 대화도 제외; 부분 정책·잊기 처리 보존 |

네 패치 모두 새 버전에도 필요했습니다. 새 번들 경로와 원본/적용 후 SHA-256을
`scripts/openclaw/runtime-patch-specs.json`에 고정했습니다. 검증기는 영수증이 주장하는 해시만
신뢰하지 않고 이 검토된 목록과 실제 파일을 비교합니다. 미검토 버전·바이트·경로는 거부합니다.

`qualify-runtime-patches.py`는 별도 후보를 만들고 실제 오프라인 함수를 검증합니다.
`--apply`는 Gateway 포트에 리스너가 없을 때만 전체 패치와 영수증을 설치합니다. 중간 쓰기나
최종 영수증 저장이 실패하면 기존 파일을 복원합니다. 후보는 설치 경로 밖에 준비해야 합니다.
경로·symlink·핀 변조·원복 경계 시험 19개가 통과했습니다. GLM 유료 추론은 추가 호출하지 않았습니다.

## 업데이트 과정에서 확인한 사항

업데이트 전 온라인 SQLite 백업과 별도 복원 검증을 완료했습니다. 실제 활성화 직전
`sessions.list` 세 표본에서 활성 작업이 없음을 확인했습니다.

2026.9.2에서 `update --no-restart`만으로는 실행 중 Gateway가 정지되지 않아 첫 Doctor가
유지보수 잠금 충돌로 거부됐습니다. 이전 패키지와 기존 프로세스가 유지됨을 확인한 뒤,
유휴 상태를 다시 확인하고 공식 `gateway stop --force` 후 업데이트를 재개했습니다.

코어 업데이트는 성공했지만 기존 Codex 2026.9.2 설치가 새 플러그인 등록 경로와 맞지 않아
재기동에 실패했습니다. 공식 2026.9.3 선언을 비교한 뒤 같은 버전의 플러그인을 정확히
설치해 복구했습니다. 최초 정지 영수증부터 정상 시작 영수증까지 약 5분 38초였습니다.
중간 실패를 업데이트 성공으로 기록하지 않았습니다.

동시에 실행된 별도 Workshop 비교 작업의 임시 에이전트는 그 작업과 조정해 정리했습니다.
그 임시 설정을 운영 정책으로 채택하거나 다른 작업의 데이터를 임의로 삭제하지 않았습니다.
향후 Gateway 변경은 같은 호스트의 다른 작업과도 유휴 구간을 조정해야 합니다.

관리 CLI의 실제 npm prefix가 누락되어 공식 dry-run이 설치 소유권을 찾지 못하던 문제도
수정했습니다. 현재 wrapper로 `update --tag 2026.9.3 --dry-run --json`이 정상 식별됩니다.
다음 버전은 반드시 새 후보에서 로컬 패치를 다시 검증한 후 적용합니다.

## 실제 확인한 동작

- macOS 기본 Python 3.9에서 관련 회귀 시험 196개가 통과했습니다. 공통 파일 해시 처리는
  파일 전체를 메모리에 올리지 않는 방식으로 Python 버전 호환성을 보완했습니다.
- Gateway가 2026.9.3 빌드 `1391f7c`로 응답하고 Telegram polling 및 핵심 플러그인 7개가 정상입니다.
- Codex 플러그인 실제 로딩에 진단 오류가 없습니다.
- 운영 데이터 없는 합성 기본 모델 요청이 Astra로 응답했고 우회 없이 임시 세션을 정리했습니다.
- 합성 회의 녹음은 Whisper→Sol/low OAuth 근거 추출→DOCX/PDF/자막 ZIP까지 생성·검증했습니다.
- 기존 5분 운영 감시기는 새 해시 목록을 포함한 설치본으로 검증 후 복구했습니다.
- 실제 공개 RSS 발표를 시험용 변경 입력으로 사용한 Sol/low 브리핑 요약도 한국어 구조와 원문 링크 검증을 통과했습니다. 이 시험은 발송하거나 운영 기준점을 바꾸지 않았습니다.
- Telegram은 안내(`142`)와 합성 회의록·PDF·전사·자막 ZIP(`143`–`146`)을 접수했습니다.
  긴 작업 조회에서도 수행 성공·검증 통과·파일 해시 확인·네 파일 전송 접수가 각각 확인됐습니다.
- 주간 command 예약 `5d5192d8-c053-4084-bc4e-40a51da74d7e`가 활성화됐고 다음 실행은
  2026-09-12 09:00 KST로 읽혔습니다. 미래 예약 실행 자체를 이미 완료했다고 기록하지 않습니다.
- 최종 설치 상태도 별도로 백업하고 격리된 복원 위치에서 파일 38,308개와 SQLite DB 28개를
  검증했습니다. 복원 파일로 운영 서비스를 교체하는 재해 복구 전환 시험은 수행하지 않았습니다.
- 설치된 작업 흐름 파일 5개와 Gateway 작업 지침이 저장소 원본과 일치합니다. 재조회한 공개
  출처에 중요 변경이 없어 주간 처리기가 모델 호출과 발송 없이 정상 종료하는 동작도 확인했습니다.

같은 CLI+RPC 명령을 각각 3회 측정한 중앙값은 다음과 같습니다. 작은 표본의 현장 측정이며,
모델 생성 속도나 일반적인 성능 향상률을 입증하는 통제 실험은 아닙니다.
