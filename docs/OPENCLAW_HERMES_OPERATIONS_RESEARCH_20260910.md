# OpenClaw + Hermes 운영 역할 확장 조사

조사일: 2026-09-10 KST. 공개 웹 자료와 현재 저장소 운영 문서를 비교한 설계 제안이다.
이 문서는 새로운 운영 권한, 예약 작업, 배포가 설치됐다는 뜻이 아니다.

## 판단

이 배포에서는 Hermes를 OpenClaw의 장애 진단·업데이트 영향 검토·개선 코드 준비 담당으로
확장하는 것이 기존 이벤트 JSON 보고서보다 실용적이다. 이는 아래 사례와 현재 배포 문제를
종합한 제안이며, 두 제품을 결합하면 성능이나 비용이 개선된다는 실측 결과는 아니다.

공개 결합 프로젝트와 사용자 경험은 확인했지만, 사용 빈도 순위·보급률·복구 성공률을
판정할 만한 대표성 있는 통계는 찾지 못했다. 이전 도구, 같은 화면에서의 선택 기능,
설계 단계 게시물은 자동 위임이 검증된 사례와 구분한다.

## 기능 중복과 추가 가치

Hermes는 복잡한 작업에서 발견한 절차와 시행착오를 스킬에 저장하고 이후 관련 작업에서
읽어 재사용하도록 설계돼 있다. 이 점은 동일 배포를 반복 관리하는 역할에 적합하다.
[Hermes Skills System](https://hermes-agent.nousresearch.com/docs/user-guide/features/skills)

현재 OpenClaw에도 경험 검토와 스킬 개선 기능이 있다. 따라서 스킬 학습 자체를 Hermes만의
기능으로 설명하거나 모든 대화를 두 실행기에 통과시키는 것은 적절하지 않다.
추가 가치는 운영 전용 지식·작업 공간, 별도 실행 경로, 그리고 다른 실행기가 만든 개선안을
독립 검증하는 역할에서 찾는 편이 낫다.
[OpenClaw Self-learning](https://docs.openclaw.ai/tools/self-learning)

현재 로컬 학습과 재사용 검증 범위는 [기존 파일럿](OPENCLAW_HERMES_PILOT.md)에 있다.
온라인 문서는 설치 시점 이후 수정될 수 있으므로, 확장 구현 때 명령과 옵션을 설치된
Hermes 0.21.1 및 OpenClaw 2026.9.3 소스와 다시 대조해야 한다.

## 이 Mac에 제안하는 작업

| 역할 | 작동 계기 | 구체적인 산출물 |
| --- | --- | --- |
| 장애 진단 | 기존 감시기의 지속 장애 판정 또는 사용자 진단 요청 | 관련 로그·상태·최근 변경을 대조한 원인 후보, 근거, 복구안 |
| 업데이트 영향 검토 | 공식 릴리스/문서 변경 감지 | 현재 설정·설치 버전·로컬 패치에 실제 관련된 변경과 호환성 검사 결과 |
| 운영 코드 개선 | 재현 가능한 버그 또는 승인된 개선 요청 | 별도 checkout의 코드 차이, 회귀 검사, 설치·원복 계획 |
| 절차 개선 | 복구·배포의 실제 검증 완료 | 적용 버전과 전제 조건을 담은 재사용 가능한 운영 스킬 |

우선 실제로 있었던 오래된 사용 제한 차단, 삭제된 임시 agent의 재시작 참조,
종료 상태 `lost`의 장기 실행 오탐을 과제로 삼을 수 있다. 이 세 문제의 당시 원인과
검증 기록은 [9월 10일 복구 문서](OPENCLAW_HEARTBEAT_RECOVERY_20260910.md)에 있다.
앞으로의 Hermes가 이를 자동 발견·수정할 수 있는지는 별도 수용 검증이 필요하다.

## 권장 연결 방식

1. 기존 5분 무추론 감시기를 상태 수집과 장애 감지 담당으로 유지한다.
2. 지속 장애나 실제 변경이 있을 때 운영 전용 Hermes를 호출한다. 정상·변경 없음에는
   추가 모델 호출을 만들지 않는다. 같은 사건은 실행 ID와 입력 해시로 중복 분석을 막는다.
3. 입력은 필요한 운영 상태·가려진 로그·코드·공식 문서로 구성한다. 일반 사용자 대화와
   인증 비밀을 무조건 통째로 공유하지 않는다.
4. Hermes가 진단과 개선 파일을 만들고, 검증 프로그램이 검사한다. 코드 수정은 별도
   checkout에서 실행하며 운영 반영은 기존 백업·검증·원복 절차를 따른다.
5. 검증된 결과를 운영 스킬로 보존한다. 스킬 증가 자체보다 실제 재사용과 다음 작업의
   정확성·시간·호출 수를 측정한다.

현재 파일 보고서 wrapper의 스킬 전용 권한으로는 이 역할을 수행할 수 없다. 운영 전용
파일 읽기, 제한된 진단 명령, 공개 문서 수집, 격리된 코드 수정·시험 경로를 추가해야 한다.

진단 실행을 OpenClaw 내부 호출에만 의존하면 Gateway 장애 시 함께 막힌다. 별도 macOS
실행 경로에서 Hermes를 시작할 수 있게 설계하고, Telegram의 기존 메시지 수신 소유권은
OpenClaw에 유지한다. Gateway가 꺼졌을 때 결과는 로컬 파일로 보존할 수 있어야 한다.
같은 Mac·네트워크·모델 공급자를 쓰는 한 해당 공통 장애까지 독립적인 것은 아니다.

## 도입 효과를 판단할 기준

- 과거 장애 증거로 원인을 구분하고 불필요한 재실행·전송을 피하는가.
- 새 버전이 기존 로컬 패치와 충돌하는지 배포 전에 검출하는가.
- 수정 후보의 실패를 검사에서 잡고 기존 대화·인증·작업 상태를 보존하는가.
- 같은 종류의 두 번째 과제에서 저장한 절차를 실제 재사용하는가.
- 무변경 상태의 모델 호출, 사건당 호출·시간, 오탐·중복 알림을 제한하는가.

먼저 장애 진단과 업데이트 영향 검토를 구현하고, 검증된 운영 코드 개선으로 넓히는 순서가
적합하다. 두 실행기 유지보수와 추가 추론 비용을 감수할 만큼 운영 부담이 줄어드는지를
현재 OpenClaw만 사용하는 기준과 비교해야 한다.
